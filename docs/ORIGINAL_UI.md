# Original UI reconstruction

The Swift frontend reads the original FAR resources. It does not embed or launch the Simitone frontend. The current game controls, interaction labels and generic dialog controls are drawn through Metal at the window's backing resolution.

## Relationships

The relationship button opens the original card panel. It uses the original BMP 2003 five-expression portraits, UnknownRel fallback, Smiley/Heart/HeartDeep icons, four RelSort button sheets and ScrollLeft/ScrollRight arrows. Each 45×90 card shows daily and lifetime numbers and bars. Family, friends, famous and all filters work on the neighborhood records without requiring target avatars on the current lot. Cards sort by daily score, then neighbor ID. Changing residents or shrinking the filtered list clamps the current page. Names and paging are available as tooltips and accessibility labels. Shared width calculations fit five cards at 800 logical pixels, ten at 1024 and fourteen at 1200. The right arrow follows the available edge. Resizing retains the previously visible item within the new page.

The original `0x004ea17e` routine establishes the mapping: daily index 0, crush index 1, lifetime index 2 and love index 3. Its mutual friendship check uses `friendship_threshold`, which `0x0045928c` reads from the simulator constants (FCNS 2 in `Global.iff`, inside `GameData/Global/Global.far`) with a built-in default of 25 at `0x00667360`. The shipped table sets it to 50. The simulation loads the table and sends each relationship's `mutualFriend` flag; the native panel falls back to 50 only when the flag is absent. Fame reads person-data index 81. Portrait selection, card dimensions and icon placement follow `0x005282ca`, `0x00528493` and `0x00528f9f`; filter/paging placement follows `0x0051d7c8`.

The current implementation passes 97 Swift tests, 276 headless relationship checks against 30 off-lot targets and 25 offscreen renders at 1600×960, 2048×1200 and 2400×1800. Rendering checks cover five/ten/fourteen-card capacities, filter ordering, page content, empty lists and indicator changes. They do not prove exact original executable pixel parity. Localized relationship descriptions, original card detail popup, the alternate taller expansion layout and custom autonomy threshold loading remain unfinished. No live game window was tested.

## Interaction menus

Clicking uses the same draw ordering, sprite alpha/depth samples and avatar triangle coverage as the renderer. Original object IDs are resolved from visible pixels. Menu requests retain the selected Sim, target and request ID; stale responses do not open a menu for another Sim or a removed object. Selecting an action sends the original interaction ID, parameter and global/local flag back to the simulator, which checks that it is still offered.

Original slash-separated category names are preserved. The telephone fixture has Services, Call Cab and Call Neighbor categories. Labels use `variablesans_10.ffn` and colors/layout recovered from `0x005ea2dd`, `0x005ea6b0`, `0x005eb598`, `0x005eac32` and `0x005eada9`. The label hit test precedes radial selection, and nested categories retain their original action parameters. Original menu appearance/selection events now use the shared native audio path. The animated Sim portrait, remaining menu sound parity and complete edge/large-menu layout parity remain missing.

The FFN parser follows the original font loader at `0x0060b933` and GIMEX's font driver. It handles v101 glyph records, signed glyph offsets, original advances/space width, a packed 4-bit coverage atlas, and bounded line wrapping. Font evidence is in `analysis/original-font-metrics.json`, `analysis/gimex-decompiled`, and the separate GIMEX Ghidra project. This is original bitmap text; full international text-entry/IME support remains unimplemented.

## Game dialogs

The initial Help System question is emitted by the real game scripts and now appears in the native app. Its response goes back to the blocked VM owner and restores the previous speed. Original expansion announcements also appear, and can be acknowledged by the player. The simulator does not automatically dismiss these prompts.

The generic dialog implementation uses `Shared/Dlg/GenDlg.bmp`, `Shared/Dlg/LBoxTile.bmp`, `Shared/Sys/WinBtn.bmp`, and the original FFN font. `SMCtrlMgrRes.RT` identifies these as the stock dialog/frame/button assets. Specialized travel, clothing, pet, phonebook and book screens are still required. Dialog icons, exact fonts/colors for each class, button pressed-state parity, sound, and richer text editing also remain incomplete.

Virtual AppKit accessibility elements expose button labels and actions for the Metal artwork. They do not create additional views. ## Live rendering investigation

Paused live resident switches can leave text or sprites missing in the window. Offscreen replay remains correct.
